## 1. 요약

1차 구현은 plan.md 13장 완료 기준(DoD) 7항목을 모두 통과한 상태였다. 그 위에서 이슈 7건을 찾아
**2건을 수정**하고 **2건을 의도적으로 보류**했으며 **3건은 문서·참고 사항으로 기록**했다.

가장 중요한 발견은 **크래시가 아니라 "조용한 오답"** 이었다. 팀원이 `dummy_data.py`에 거래를 하나
잘못 넣으면, 에러 없이 `[제안] 이번 달 절감 여지 없음`이 나와서 원인을 찾기가 매우 어려웠다.
이걸 막는 가드를 넣은 것이 이번 수정의 핵심이다.

| | 건수 |
|---|---|
| 수정 완료 | 2 (이슈 1·2) |
| 보류 (이유 기록) | 2 (이슈 3·4) |
| 참고·문서 사항 | 3 (이슈 5·6·7) |

**C1~C6 함수 로직(`src/c1_clean.py` ~ `src/c6_suggest.py`)과 더미 데이터(`src/dummy_data.py`)는
한 줄도 바뀌지 않았다.** 수정 범위는 `src/main.py`, `tests/test_pipeline.py`,
`tools/build_notebook.py` 세 파일이다.

## 4. 수정한 것

### 4-1. 거래월 3개 전제 가드 추가

**이슈 1 · 등급: 높음 · 파일: `src/main.py`, `tests/test_pipeline.py`**

#### 무엇이 문제였나

`run_pipeline`은 `this_month = max(거래월)`로 이번 달을 정한다. 07~09 밖의 월이 하나라도 생기면
그 달이 이번 달이 되고, 그 달엔 지출이 1건뿐이라 최저가 되어 모든 카테고리가 C5에서 걸러진다.
동시에 C3의 "대상 월 3개" 조건(plan.md 7장 C3 규칙 1)도 깨져서 `쿠팡 와우멤버십` 고정 보정까지 멈춘다.

**재현** — 기본 더미 데이터에 거래 1건만 더해보면:

| 넣은 거래 | 수정 전 결과 |
|---|---|
| `{"date": "2026-10-05", "merchant": "스타벅스 한양대점", "amount": 5600}` | `[제안] 이번 달 절감 여지 없음` |
| `{"date": "2026-O9-05", ...}` (숫자 0 대신 영문 O 오타) | `[제안] 이번 달 절감 여지 없음` |

두 경우 모두 **예외도, 경고도 없이** 틀린 답이 나온다. 스택 트레이스가 없으니 원인 추적이 가장
어려운 유형이고, 11/18 통합 체크포인트나 영상 녹화 중에 터지면 시간을 크게 잡아먹는다.

#### 어떻게 고쳤나

`src/main.py` 상단에 상수 1개:

```python
EXPECTED_MONTH_COUNT = 3   # plan.md 8장 결정사항 3 — 더미 데이터는 2026-07~09 세 달
```

`run_pipeline`의 빈 입력 처리 바로 다음에 가드 4줄:

```python
    # 정상 거래가 하나도 없으면 후보 0개로 보고 C6에 빈 리스트를 넘긴다
    if len(months) == 0:
        return make_suggestion([])

+   # 거래월이 3개가 아니면 "최근 3개월" 전제가 깨진 것이다.
+   # 이때 C3 고정 보정이 멈추고 this_month도 엉뚱한 달이 되어 결과가 조용히 틀리므로,
+   # 제안 문장 대신 원인을 알려 준다 (더미 데이터의 date 오타를 바로 찾기 위함).
+   if len(months) != EXPECTED_MONTH_COUNT:
+       return (
+           "[경고] 거래월이 {}개다 ({}). 최근 3개월 전제가 깨져 제안을 만들 수 없다. "
+           "dummy_data.py의 date를 확인하라."

+
    this_month = max(months)
```

`tests/test_pipeline.py`에 테스트 1개 추가 (25개 → 26개):


| 입력 | 수정 전 | 수정 후 |
|---|---|---|
| 기본 더미 (07·08·09) | `[제안] 카페·간식: 이번 달 187,000원…` | **동일** |

| 날짜 오타 `2026-O9-05` | `[제안] 이번 달 절감 여지 없음` ← 조용한 오답 | `[경고] 거래월이 4개다 (2026-07, 2026-08, 2026-09, 2026-O9). …` |

#### 설계 판단

- **예외를 던지지 않고 문자열을 반환**했다. plan.md 13장 DoD의 "예외 없이 문장 1줄 반환"을 지키고,
  Colab "모두 실행"에서 빨간 트레이스백이 뜨지 않게 하기 위해서다.
- **C3는 그대로 뒀다.** plan.md 7장 C3 규칙 1이 "대상 월이 3개가 아니면 아무것도 바꾸지 않고
  복사본을 반환한다"로 명시돼 있어, C3가 조용히 넘어가는 건 스펙대로다. 가드는 전체 흐름을

- **`plan.md` 수정은 필요 없다.** 8장 결정사항 3이 이미 "최근 3개월은 데이터에 존재하는 3개
  거래월"로 전제를 못 박아 뒀고, 이 가드는 그 전제를 코드로 옮긴 것이다.

### 4-2. 한글 지역 변수 → snake_case

**이슈 2 · 등급: 중간 · 파일: `tests/test_pipeline.py`(48줄), `tools/build_notebook.py`(13줄)**

#### 무엇이 문제였나

동작 오류는 **전혀 없다.** 파이썬 3은 한글 식별자를 정상 허용한다. 문제는 두 가지다.

1. plan.md 4장이 "지역 변수도 snake_case로 통일한다"고 **우리가 직접 정한 규칙**인데 이를 어겼다.
2. `tools/build_notebook.py`의 `테스트_목록` / `이름` / `입력`은 **제출 노트북 마지막 셀에
   그대로 들어간다.** 채점자가 보는 코드에 우리 규칙 위반이 노출된다.

`src/`의 솔루션 코드(C1~C6, main, dummy_data)는 처음부터 전부 영어 snake_case여서 문제가 없었다.

#### 어떻게 고쳤나 — 치환표 (10개)

| 원래 | 수정 후 | 위치 |
|---|---|---|
| `원본` | `raw_transactions` | tests (7곳) |
| `결과` | `result` | tests (20곳) |
| `거래` | `transaction` | tests 루프 (10곳) |
| `항목` | `item` | tests (8곳) |
| `카테고리들` | `categories` | tests (3곳) |
| `테스트_목록` | `test_cases` | build_notebook → **노트북 셀** |
| `이름` | `name` | build_notebook → **노트북 셀** |
| `입력` | `data` | build_notebook → **노트북 셀** |
| `원본_줄들` | `source_lines` | build_notebook (5곳) |
| `남긴_줄들` | `kept_lines` | build_notebook (5곳) |
| `줄` | `line` | build_notebook (4곳) |

출력 문자열(`"엣지: 후보 0개"` 등)과 주석·docstring은 **한국어 그대로** 유지했다
(plan.md 4장 "주석과 docstring은 한국어로 작성한다").

#### 제출 노트북 마지막 셀 — 수정 전 / 후

```python
# ── 수정 전 ───────────────────────────────────────
테스트_목록 = [
    ("정상 (기본 더미 데이터)", transactions),
    ...

for 이름, 입력 in 테스트_목록:
```


`test_정상_케이스`, `test_월_2건_이상이면_재량_유지` 같은 이름은 **바꾸지 않았다.**

- `python -m unittest discover tests -v` 출력이 plan.md 10장 결과표 재료로 그대로 쓰인다.
  영어로 바꾸면 보고서 작성 시 다시 번역해야 한다.

- 13장 DoD도 "**함수명·키 이름**이 이 문서 및 기획서와 일치"만 요구한다.

이 판단은 `tests/test_pipeline.py` 모듈 docstring에도 적어 뒀다. 팀에서 다르게 정하면 바꾸면 된다.

## 5. 수정하지 않은 것과 이유

### 이슈 3 — C1을 통과한 거래가 C2에서 예외를 내는 경로 (보류)

`src/c1_clean.py`의 날짜 검사는 **길이 10과 `-` 위치만** 보고 숫자 여부를 확인하지 않는다
(plan.md 7장 C1 규칙 5를 문구 그대로 구현한 결과다). 그래서 이런 입력이 C1을 통과한다.

| 입력 | 결과 |
|---|---|
| `{"date": "2026-09-XX", ...}` | `ValueError` — `c2_label.py`의 `int(date[8:10])` |
| `{"merchant": 123, ...}` | `TypeError` — `c2_label.py`의 `keyword in merchant` |
| `[None]` (거래가 dict가 아님) | `TypeError` — `c1_clean.py`의 `key not in transaction` |

**보류 이유**

1. **도달 불가 경로다.** 입력원은 `src/dummy_data.py`의 하드코딩 리터럴 하나뿐이다
   (CSV 읽기·사용자 입력·네트워크 없음 — plan.md 2장 제약). 기본 더미 66건을 전수 검사한 결과
   위험한 값은 **0건**이었다.
2. 고치려면 `plan.md` 7장 C1 규칙 5도 같이 수정해야 해서 비용이 커진다.
3. 현실적으로 더 위험한 변종(날짜 오타로 월이 늘어나는 경우)은 **이슈 1의 가드가 이미 막는다.**
   그쪽이 같은 위험을 더 싼 값에 처리한다.

실제 CSV 입력을 받는 방향으로 범위가 바뀌면 그때 C1을 보강하면 된다.

### 이슈 4 — `round()`의 banker's rounding (유지)

파이썬 `round()`는 정확히 `.5`인 값을 짝수로 보낸다. plan.md 8장 결정사항 5가 `round(repeat_ratio * 100)`을
명시했으므로 그대로 뒀지만, 숫자를 손계산할 때 주의해야 한다.

| `repeat_ratio` | × 100 | `round()` |
|---|---|---|
| `8/13` = 0.61538… | 61.538…% | **62** ← 현재 기대 문장 |
| 0.625 | 62.5% | **62** (63 아님) |
| 0.5 | 50.0% | **50** |

현재 식비의 2026-09 반복 비율이 정확히 `0.625`다. 나중에 더미 데이터를 조정해 식비가 1위가 되면
기대 문장은 `63%`가 아니라 **`62%`** 가 된다.

| 각 함수 docstring에 Input / Process / Output 명시 | 통과 |

추가 확인:

- 정상 출력: `[제안] 카페·간식: 이번 달 187,000원, 최근 3개월 최저 120,000원(2026-07) → 절감 여지 67,000원, 반복 결제 62%`
- plan.md 9장 목표 수치 전부 일치 — 카페·간식 `120,000 / 150,000 / 187,000`,
  식비 `200,000 / 180,000 / 210,000`, 쇼핑 `95,000 / 78,000 / 42,000`,
  반복 비율 `8/13` → 62%, 점수 `0.4611`(1위) vs 식비 `0.3357`(2위), 쇼핑 제외
- C3 재분류: `쿠팡 와우멤버십` 3건만 고정으로 변경. `메가커피 왕십리점`(매월 6일 4,500원이지만
  09월에 4건)은 월 1건 조건 실패로 재량 유지 — plan.md 9장의 반례 의도대로 동작
- 노트북 재빌드 재현성: 두 번 빌드 → md5 동일
- 한글 식별자 잔존: 0건 (메서드명 제외)
- 노트북에 가드 반영: `EXPECTED_MONTH_COUNT`, `[경고] 거래월이` 포함 확인

## 7. plan.md에 반영이 필요한 항목

코드가 아니라 문서를 고쳐야 하는 것들이다. **팀 확인이 필요하다.**

### 7-1. 9장 더미 데이터 건수 (이슈 6)

plan.md 9장은 "3개월치 약 30~45건"이라고 썼지만 실제 더미 데이터는 **66건**(C1 정제 후 64건)이다.

이유: 9장 표가 2026-09 카페·간식을 **13건 고정**으로, 합계를 **187,000원**으로 못 박았다.
건당 평균 14,385원이라 07·08월과 식비·쇼핑·교통·구독료까지 채우면 45건 안에 들어가지 않는다.
금액은 DoD("글자 하나까지 일치")에 걸리고 건수는 추정치라, 금액을 우선했다.

| 선택지 | 작업 |
|---|---|
| **A (권장)** | 9장의 "약 30~45건" 문구를 "약 60~70건"으로 수정 |
| B | 금액을 전부 낮춰 45건 이하로 재설계 → 9장 표·10장 기대 문장·테스트 전부 수정 |

### 7-2. 상수 위치 (이슈 7)

plan.md 4장은 "상수는 `src/dummy_data.py` 상단 **또는 각 모듈 상단**에 대문자로 둔다"고 했고,
예시로 세 상수를 함께 보여 줬다. 실제로는 **사용하는 모듈 상단**에 나눠 뒀다.

| 상수 | 위치 |
|---|---|
| `FALLBACK_CATEGORY = "기타"` | `src/c2_label.py` |
| `SAVING_WEIGHT = 0.6`, `REPEAT_WEIGHT = 0.4` | `src/c5_savings.py` |
| `REQUIRED_KEYS` | `src/c1_clean.py` |
| `TARGET_MONTH_COUNT = 3` | `src/c3_fixed.py` |
| `EXPECTED_MONTH_COUNT = 3` | `src/main.py` |

이유: `dummy_data.py`에 두면 C2·C5가 `from src.dummy_data import ...`로 가져와야 하는데,
그 줄은 `# notebook:skip`으로 지워지므로 **노트북에서 `NameError`가 난다**
(plan.md 2-1장 자체 완결형 요구사항과 충돌). 4장이 허용한 범위 안이라 문서 수정은 필수가 아니지만,
예시 블록 위치가 헷갈릴 수 있어 기록해 둔다.

### 7-3. 노트북 셀 분할 (참고)

plan.md 3-1장은 "코드: `main` 정의 + `main()` 호출"을 한 항목으로 적었다. 실제 노트북은
`main` 정의 셀 → 마크다운("9. 실행 결과") → `main()` 호출 셀로 나눴다. 출력 셀이 어디인지
발표·녹화 때 가리키기 쉽게 하려는 의도다. 문제가 되면 합치면 된다.

## 8. 팀에 공유할 주의사항

### 더미 데이터를 수정할 때 (고준호)

- **2026-07 / 08 / 09 밖의 날짜를 넣지 말 것.** 넣으면 `[경고] 거래월이 N개다 …`가 출력된다.
  이건 버그가 아니라 의도된 가드다. 날짜를 고치면 정상으로 돌아온다.
- 금액을 바꾸면 **plan.md 10장 기대 문장과 `tests/test_pipeline.py`의 `EXPECTED_NORMAL`을 같이
  고쳐야 한다.** 안 고치면 `test_정상_케이스`가 실패한다.
- 같은 `(date, merchant, amount)` 조합을 새로 넣으면 C1이 중복으로 보고 1건만 남긴다
  (plan.md 8장 결정사항 6). 의도한 중복 1건 외에는 날짜를 다르게 둘 것.
- 재량 카테고리 가맹점을 3개월 모두 **같은 일·같은 금액·월 1건**으로 넣으면 C3가 고정으로
  바꿔서 합계에서 빠진다. `쿠팡 와우멤버십` 외에는 이런 패턴을 만들지 말 것.

### 함수를 수정할 때 (전원)

- 수정 후 반드시 두 명령을 돌릴 것. 둘 중 하나라도 깨지면 수정이 끝난 게 아니다.
  ```bash
  python -m unittest discover tests   # 26개 전부 통과해야 함
  python -m src.main                  # 기대 문장과 일치해야 함
  ```
- `src/*.py`를 고쳤으면 **노트북을 반드시 재생성**한다. 노트북을 직접 편집하지 않는다.
  ```bash
  python tools/build_notebook.py
  ```
- `src` 모듈끼리 import하는 줄에는 끝에 `# notebook:skip`을 붙인다. 안 붙이면 노트북이
  Colab에서 `ModuleNotFoundError`로 죽는다.
