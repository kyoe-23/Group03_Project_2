## 1. 프로젝트 개요

Project 1(개인, 2~7주차)에서는 컴퓨터 없이 추상화·분해·패턴 인식으로 각자의 8시간 문제(8HR 문제)를 설계하고 3분 영상으로 발표했습니다. 9~13주차에는 그 논리를 옮길 언어 — 순차, 함수, 조건, 반복, List·Dict — 를 배웠습니다.

Project 2는 이 두 흐름이 만나는 곳입니다. 팀원 3명의 8HR 문제 중 하나를 골라, 팀이 함께 설계하고, 실제로 돌아가는 Python 코드로 증명합니다.

### 핵심 질문

**"내가 머리로 설계한 논리가, 팀의 코드로 실제로 돌아가는가?"**
— 생각이 먼저, 코드는 그 번역입니다.

### 프로젝트 목표

- 팀원 3명의 8HR 문제를 5가지 기준으로 공정하게 비교·선정하기
- 선정한 문제를 IPO 파이프라인과 함수 단위로 설계하고 역할 나누기
- 9~13주차 개념(순차·함수·조건·반복·List/Dict)을 하나의 MVP로 통합하기
- 3분 영상 + Miro 발표공간으로 "문제 → 사고 → 코드 → 결과" 증명하기
- 동료 피드백과 성찰로 서로에게서 배우기

### Project 1과 무엇이 달라지나

| 구분 | Project 1 (개인) | Project 2 (그룹) |
|---|---|---|
| 문제 | 내가 정의한 8HR 문제 | 3개 후보 중 팀이 선정한 1개 |
| 결과물 | 워크시트 + 다이어그램 (종이 위 논리) | 동작하는 Colab 코드 (실행되는 논리) |
| 분해 | 컴포넌트 3개 이상 + IPO | 컴포넌트 = 함수, 팀원별 담당 |
| 연결 | Output → Input 을 그림으로 | Output → Input 을 코드로 실행 |
| 발표 | 3분 영상 (본인) | 3분 영상 (전원 목소리) + Miro 발표공간 |

## 2. 팀 구성 절차 (Opt-in)

전국 온라인 수업이라 직접 만나기 어렵기 때문에, LMS에서 스스로 팀을 찾고(self-signup), 못 찾은 학생은 교수자가 지정 배정합니다. 팀은 3인 1조입니다.

| 단계 | 시점 | 주체 | 활동 |
|---|---|---|---|
| 1 | 11주차 강의 오픈 전까지 | 교수자 | "팀 구성 안내" 게시 + "팀원 모집" 게시판 오픈 |
| 2 | ~ 10/18(일) 23:59 까지 | 학생 | 아래 상세 활동 참고 |
| 3 | 10/18(일) 23:59 까지 | 학생 | self-signup 마감 |
| 4 | 10/20(화) | 교수자 | 미구성 학생 지정 배정 → 조편성표 공지 (조 번호 Group 01~, 팀장 Y/N) |
| 5 | 10/20(화) | 교수자 | LMS 팀 프로젝트방 생성 + 조별 Miro 보드 이메일 초대장 발송 |
| 6 | 10/25(일) 23:59 까지 | 팀 | Miro 보드 초대 수락, 팀 채널·자기소개·소통방식 결정, 운영 역할 분담, 팀 프로젝트방 게시판에 계약서 Part A 업로드 |

**2단계 상세 활동**

1. 모집자: 교수자의 "팀원 모집" 글에 댓글로 [내 8HR 문제 한 줄] + [Project 1 영상 링크]를 올립니다.
2. 참여 희망자: 마음에 드는 모집 댓글에 답글로 참여 의향을 남깁니다. 예: "참여 희망합니다 — 이름·학번, 잘하는 것(데이터/코딩/영상)"
3. 모집자: 답글 단 사람 중 2명을 골라 교수자의 "팀 구성 안내" 글에 댓글을 답니다. 내용은 팀원 3명 이름·학번, 팀장(=모집자)입니다.
4. 선택되지 않은 학생: 다른 모집 댓글에 다시 답글을 달거나, 직접 모집자가 됩니다. 10/18(일) 23:59 까지 팀이 없으면 지정 배정됩니다.

> **주의: 이메일 확인은 필수**
> Miro 보드는 수강신청자 회원정보의 메일 주소로 초대장이 갑니다. 프로젝트 가이드 공지 시 안내된 방법으로 확인하지 않으면 보드에 들어갈 수 없습니다.

### 역할

| 구분 | 역할 | 하는 일 |
|---|---|---|
| 운영 역할 | 팀 리더 | 일정 총괄, 교착 시 최종 결정, 제출 확인, 교수자 연락 창구 (보통 팀을 모집한 학생, 아닐 경우 랜덤 배정) |
| 운영 역할 | 기록 담당 | 회의록, 비교 평가표·선정 결정서 문서화, Miro 정리 |

### 협업 철칙 4가지

1. 모든 팀원은 핵심 함수를 최소 1개 직접 작성하고, 다른 팀원 함수 1개 이상을 코드 리뷰한다.
2. 작업마다 책임자는 정확히 1명이다.
3. 영상에는 팀원 전원이 본인 목소리로 참여한다.
4. 연락 두절·역할 미수행이 LMS 기록으로 확인되면, 팀을 이끈 학생은 그대로 그룹 프로젝트로 평가받고(범위가 작아져도 만점 가능), 미참여자는 0점 또는 개인 프로젝트(그룹 프로젝트 만점의 50%가 최고점)로 처리한다.

## 3. 우리 팀 문제 고르기

팀의 후보는 팀원 3명 각자의 Project 1 8HR 문제입니다. 5가지 기준으로 비교해 1개를 고릅니다. 그 전에 "좋은 팀 문제"가 무엇인지 알아 두세요.

### 좋은 팀 문제의 4가지 조건

1. **현실성** — 누군가의 일상에 실제로 있는 문제
2. **계산적 성격** — 데이터와 규칙(if·for)으로 풀 수 있는 문제 (단순 의견 문제 X)
3. **1주 구현 가능 범위** — 핵심 로직을 15주차 한 주 안에 Colab에서 시연할 수 있는 크기
4. **3인 분담 가능성** — 3개 이상 함수로 나뉘고, 한 함수의 Output이 다음 함수의 Input이 되는 구조

### 크기 감 잡기

| 너무 큼 | 딱 좋음 | 너무 작음 |
|---|---|---|
| 캠퍼스 종합 배달 플랫폼 | 비 오는 금요일, 주문 5건·라이더 3명 배차 규칙 | 거리 하나 계산하기 |
| 전국 맛집 추천 앱 | 친구 3명 취향으로 오늘 저녁 식당 1곳 | 추천 식당 이름 입력하면 평점 출력 |
| AI 학습 관리 시스템 | 내 시간표·시험일 기준 일별 공부시간 분배 | 오늘 공부시간 입력·출력 |

### 좋은 팀 문제 vs 나쁜 팀 문제

| 나쁜 팀 문제 | 왜? | 좋은 팀 문제로 바꾸면 |
|---|---|---|
| "AI로 최적의 배달 경로를 찾는다" | 머신러닝·지도 API 필수, 1주 불가 | "주문 5건·라이더 3명, 반경 3km 안에서 가장 가까운 라이더 배차" |
| "실시간 버스 도착 정보를 알려 준다" | 실시간 데이터 수집이 전부 | "셔틀 시간표(List)로 강의 시작 전 가장 늦게 타도 되는 셔틀 찾기" |
| "좋은 스터디 조를 만든다" | "좋은"을 측정할 수 없음 | "가능 시간대 겹침 수가 가장 큰 3인 조합 찾기" |
| "문자가 스미싱인지 판단한다" (한 함수로) | 분해 없이 함수 1개 | "문자 List → 키워드 점수 → 위험도 분류 → 경고 출력" 4단계 |

### 주제 예시 풀 (Project 1 문제가 약할 때 참고)

| 분야 | 예시 문제 | IPO 한 줄 |
|---|---|---|
| A 이동·배달 | 라이더 배차 / 셔틀 대기시간 / 따릉이 반납 위치 | 주문·기사 List → 반경 필터 → 최근접 선택 → 배차 결과 |
| B 학습·시간 | 시험 공부 분배 / 과제 마감 우선순위 / 조모임 시간 찾기 | 과제 List → 마감·난이도 점수 → 정렬 → 오늘 할 일 3개 |
| C 추천·매칭 | 식당·영화 추천 / 룸메이트 매칭 / 스터디 조 편성 | 취향 Dict → 적합도 점수 → 정렬 → Top 1 + 이유 |
| D 탐지·분류 | 스미싱 경고 / 지출 분류 / 중복 일정 탐지 | 문자 List → 키워드 점수 → 위험도 분류 → 경고 |
| E 캠퍼스·생활 | 학식 메뉴 선택 / 도서관 좌석 / 분리수거 안내 | 품목 입력 → 규칙표 매칭 → 분류 → 안내 문구 |

## 5. 14주차 Phase 1: 6단계 워크숍

온라인 팀 회의 1회(약 95분)로 진행하는 것을 권장합니다. 회의 전에 각자 3분 공유를 준비하세요 — Project 1 워크시트와 영상을 바탕으로 하면 됩니다.

| 단계 | 시간 | 핵심 |
|---|---|---|
| Step 1 공유 | 15분 | 인당 3분 + 2분 질문. 비판은 보류, 이해에 집중 |
| Step 2 비교 | 15분 | 5기준 × 1~5점 = /25 |
| Step 3 선정 | 15분 | 점수 리뷰 3 + 상위 2개 토론 5 + 투표 2 + 결정서 5 |
| Step 4 점검 | 15분 | 구현 가능성 6항목 O/X |
| Step 5 분담 | 10분 | 함수별 책임자 1명·리뷰어 → 계약서 Part B |
| Step 6 설계 | 25분 | 스키마 · IPO · 함수 뼈대 · 마일스톤 |

### Step 1 · 공유 (Elevator Pitch)

3분 안에 다섯 가지를 말합니다.

1. 문제 정의: 누구의 어떤 문제인가
2. 해결 범위: 어디까지 다루고 어디서 끊는가
3. 핵심 컴포넌트 3개
4. IPO 요약: 입력과 출력의 흐름
5. 예상 데이터·리스크 1~2개

듣는 사람은 가치(Impact)와 구현 난이도(Feasibility)를 메모합니다. 같은 내용을 Miro Zone 1 후보 카드로 남깁니다.

### Step 2 · 비교 평가표

| 기준 | 질문 | 1점 | 5점 |
|---|---|---|---|
| 가치 · Impact | 사용자에게 의미 있는 개선을 만드는가? | 사소한 불편 해소 | 핵심 불편을 확실히 해결 |
| 실현성 · Feasibility | 1주 안에 프로토타입이 가능한가? | 범위가 커서 1주 내 불가 | 핵심 로직 시연 확신 |
| 데이터 · Data | 쓸 수 있는 데이터가 있는가? | 수집 불가·대체재 없음 | 바로 사용 가능 / 더미로 대체 가능 |
| 모듈성 · Modularity | 3명이 함수로 나눠 병렬 작업할 수 있는가? | 분해 불가·충돌 심함 | 명확한 IPO로 3인 분담 |
| Python 준비도 | 수업에서 배운 기능으로 충분한가? | 고난도 외부 지식 필수 | List·Dict·if·for·함수로 충분 |

### Step 3 · 선정과 결정서

- 점수 합산 → 차이가 큰 항목 짧게 의견 교환 → 상위 2개 집중 토론 → 1인 1표.
- 동점이면 실현성(Feasibility)이 높은 쪽을 고릅니다.
- 결정서(Decision Log)에 3가지를 남깁니다.
  - 선정 사유 (5기준 근거)
  - 리스크와 대응 (더미 데이터, 범위 축소 등)
  - 탈락 아이디어의 부분 통합 가능성

### Step 5 · 역할 분담 (RACI)

### 모델 케이스: 가장 가까운 배달 가능 라이더 찾기

9~13주차 개념이 한 프로그램에 모두 들어 있습니다. 이 코드는 Colab에서 그대로 실행됩니다.

```python
# ── 0. 데이터 준비 (13주차: List of Dicts) ─────────────────
orders = [
    {"id": "O1", "x": 2.0, "y": 1.0, "menu": "라멘"},
    {"id": "O2", "x": 5.0, "y": 4.0, "menu": "스테이크"},
    {"id": "O3", "x": 9.0, "y": 9.0, "menu": "피자"},
]
drivers = [
    {"name": "김라이더", "x": 1.0, "y": 1.0, "is_available": True},
    {"name": "이라이더", "x": 4.0, "y": 5.0, "is_available": True},
    {"name": "박라이더", "x": 3.0, "y": 2.0, "is_available": False},
]

# ── 1. 거리 계산 (10주차: 함수) ─────────────────────────
def calc_distance(a, b):
    """두 지점(dict)의 직선 거리(km)를 반환"""
    return ((a["x"] - b["x"]) ** 2 + (a["y"] - b["y"]) ** 2) ** 0.5

# ── 2. 후보 필터링 (11주차 조건 + 12주차 반복) ─────────────
def find_nearby_drivers(order, drivers, radius=3.0):
    """배달 가능하고 반경 안에 있는 기사 목록을 반환"""
    candidates = []
    for d in drivers:
        if d["is_available"] and calc_distance(order, d) <= radius:
            candidates.append(d)
    return candidates

# ── 3. 최적 기사 선택 ───────────────────────────────────
def assign_driver(order, candidates):
    """가장 가까운 기사 1명을 반환 (없으면 None)"""
    if len(candidates) == 0:                 # 엣지 케이스: 후보 0명
        return None
    best = min(candidates, key=lambda d: calc_distance(order, d))
    best["is_available"] = False             # 상태 업데이트
    return best

# ── 4. 결과 출력 (9주차: 순차) ──────────────────────────
def print_result(order, driver):
    if driver is None:
        print(f"[대기] {order['id']} {order['menu']} → 3km 안에 배달 가능한 기사 없음")
    else:
        dist = calc_distance(order, driver)
        print(f"[배차] {order['id']} {order['menu']} → {driver['name']} ({dist:.1f}km)")

# ── main: C1 출력이 C2 입력이 되는 파이프라인 ──────────────
for order in orders:
    candidates = find_nearby_drivers(order, drivers)   # C1 → candidates
    driver = assign_driver(order, candidates)          # candidates → C2
    print_result(order, driver)                        # C2 → 출력
```

실행 결과:

```
[배차] O1 라멘 → 김라이더 (1.0km)
[배차] O2 스테이크 → 이라이더 (1.4km)
[대기] O3 피자 → 3km 안에 배달 가능한 기사 없음
```

### 사고법이 코드에서 어디에 보이나

| 사고법 | 코드에서 어디에 보이나 |
|---|---|
| 추상화 | Keep: 좌표·배달 가능 여부 / Drop: 라이더 평점·오토바이 종류·실제 도로망 (직선 거리로 단순화) |
| 분해 (IPO) | `find_nearby_drivers` → candidates → `assign_driver` → driver → `print_result` |
| 패턴 | 거리 계산이 필터링과 최적 선택 두 곳에서 반복 → `calc_distance` 함수로 추출해 재사용 |
| 엣지 케이스 | O3 피자: 반경 안 후보 0명 → 에러 없이 [대기] 출력 |

## 13. AI 도구 사용 원칙

- ChatGPT 등 생성형 AI는 아이디어 탐색, 오류 메시지 해석, 코드 점검 보조로 사용할 수 있습니다.
- 내가 설명할 수 없는 코드는 제출하지 않습니다. AI 도움을 받은 셀에는 `# AI 보조:` 주석을 답니다.
- 더미(가상) 데이터는 "더미(가상)"라고 밝힙니다. 실제 데이터를 쓰면 출처를 README에 적습니다.
- 영상 내레이션에 AI 음성(TTS·보이스 클로닝)을 사용하지 않습니다.

### 왜 이렇게 하나요?

AI는 그럴듯하지만 틀린 코드를 자주 만듭니다. 이 프로젝트의 목표는 내 논리를 코드로 번역하는 경험이지, 코드를 얻는 것이 아닙니다. 영상의 "③ 핵심 코드" 장면에서 여러분이 직접 설명할 수 있어야 합니다.

## 14. 자주 묻는 질문 (FAQ)

**Q. 전국 학생이라 같은 시간에 모이기 어렵습니다.**
프로젝트는 비동기로 설계되어 있습니다. 14주차 팀 회의 1회만 시간을 맞추면 되고, 그것도 어렵다면 Step 1~6을 팀 채팅에서 단계별로 진행해도 됩니다.

**Q. 우리 팀 3명 문제가 모두 약하면요?**
3장의 주제 예시 풀에서 하나를 가져와 팀 문제로 다듬어도 됩니다. 결정서에 이유를 적으세요.

**Q. 파이썬을 잘하는 팀원이 혼자 다 짜면 안 되나요?**
안 됩니다. 모든 팀원이 함수 1개 이상의 책임자여야 하고, 채점에 반영됩니다. 잘하는 팀원은 리뷰어와 통합 담당으로 도와주세요.

**Q. numpy나 pandas를 써도 되나요?**
써도 되지만 필수는 아닙니다. 수업에서 다룬 List·Dict·if·for·함수로 충분한 문제를 고르는 것이 비교 기준(Python 준비도)입니다.

**Q. 15주차 중간에 문제를 바꿔도 되나요?**
범위 축소는 언제든 좋습니다.

**Q. 코드가 끝까지 안 돌아가면 0점인가요?**
아닙니다. 마지막으로 돌아간 버전을 제출하고, 막힌 부분과 원인을 Zone 5 "한계"에 솔직히 적으면 부분 점수를 받습니다.

**Q. Miro 유료 플랜이 필요한가요?**
아니요. 보드는 교수자 계정에 있고, 여러분은 이메일 초대로 편집합니다. 무료 계정으로 충분합니다.

**Q. 팀원이 연락이 안 돼요.**
계약서 6조: 1차 대화 → 2차 팀 채널 기록 → 3차 팀 리더가 LMS 메시지로 교수자에게 보고. 이 경우 팀을 이끈 학생은 그대로 그룹 프로젝트로 평가받습니다(범위가 작아져도 만점 가능). 미참여자는 0점 처리되거나, 개인 프로젝트로 전환해 수행합니다(그룹 프로젝트 만점의 50%가 최고점).
